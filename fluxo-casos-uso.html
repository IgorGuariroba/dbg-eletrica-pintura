1. Chega na Landing Page

Acessa o site via Google, indicação ou link direto. Vê serviços oferecidos, portfólio antes/depois, avaliações reais e CTA principal: "Descreva seu problema e receba um orçamento".

Landing Page

2. Preenche Formulário de Solicitação

Formulário de taps — mínimo de digitação. WhatsApp (único campo digitado), categorias em cards visuais (Elétrica / Pintura / Drywall — múltipla seleção permitida), fotos opcionais (botão câmera/galeria), data desejada (date picker), duração estimada (chips: <1h / meio dia / dia inteiro / +1 dia / não sei), descrição por áudio (transcreve via Web Speech API) ou texto livre opcional. Endereço obrigatório, método de input opcional: compartilha localização atual (Geolocation API + BrasilAPI pra geocoding reverso, 1 tap), ou digita CEP (ViaCEP preenche rua, bairro, cidade; resta só número e observação), ou digitação manual (último recurso). Mínimo obrigatório: CEP + número. Antes do envio: checkbox LGPD com link pra política de privacidade e termos (finalidade explícita dos dados, direito de exclusão). Sem aceite, não envia. Envio cria 1 Solicitação (pode gerar N ordens de serviço — 1 por categoria/especialidade). Usuário criado pelo número — sem senha, sem login.

Formulário Low-Friction + LGPD

3. Confirmação + Envio via WhatsApp (wa.me)

Formulário enviado → tela de confirmação no site: "Solicitação #XXX criada" com link da solicitação. Em seguida, redireciona pro WhatsApp da empresa via wa.me com mensagem pré-preenchida (dados do form + link). wa.me = abrir conversa (grátis, sem API). Cliente sabe que foi registrado mesmo se atendimento humano demorar. Mesmo link pra todos — role detection por cadastro no banco.

Confirmação + wa.me

4. Acesso ao Site (com ou sem Google)

Cada solicitação tem URL única: site.com/s/{token}. Dois modos de acesso: (A) Sem login (token) — versão limitada: aprovar/rejeitar orçamento (com código de verificação WhatsApp), ver status, avaliar. Ações com impacto operacional (reagendamento, cancelamento, acionar garantia) não disponíveis por token — requer Google OAuth no site ou wa.me pro número da empresa (atendimento humano). Dona Maria funciona 100% por WhatsApp + links. (B) Com Google OAuth — portal completo: histórico de todas OS, múltiplas solicitações, faturas, documentos, link de indicação sempre acessível, reagendamento, cancelamento e acionamento de garantia pelo site. Primeiro Google a acessar vincula ao número do form. Outro Google → bloqueado. Admin pode desvincular Google no módulo Equipe (edge case: vinculação errada). Role detection: e-mail na tabela de membros → visão técnico/admin. Senão → visão cliente.

Token + Google OAuth

5. Recebe Orçamento Digital

Técnico monta orçamento no link da solicitação (itens do catálogo com preço único embutindo material + mão de obra × quantidade + deslocamento separado = total). Notificação "orçamento pronto" por fase: Fase 1 = admin envia wa.me manualmente com link. Fase 2 = + e-mail automático (Resend). Fase 4 = + WhatsApp Cloud API. Orçamento válido por 7 dias (expiração lazy até Fase 4, cron a partir da Fase 4) — lembrete dia 3 e dia 6 (mesma escada de fases). Sem resposta no dia 7 → expira e entra no remarketing. Toda comunicação registrada no sistema — ativo de dados pra insights e melhorias.

Orçamento 7 dias + Rastreio

6a. Aprova Orçamento ✓

Aprova no app com assinatura digital. Sistema libera agendamento — escolhe data e horário disponíveis.

6b. Rejeita Orçamento ✗

Rejeita com motivo opcional. Solicitação encerrada. Histórico salvo no portal. Remarketing 48h (Fase 1: admin wa.me manual; Fase 2: e-mail Resend; Fase 4: + Cloud API).

7. Agendamento após Aprovação

Orçamento aprovado → agendamento evolui por fase. Fase 1-2: admin atribui técnico e define data manualmente (equipe pequena, cliente solicita data desejada no formulário). Admin comunica data confirmada via wa.me. Fase 3: sistema mostra slots disponíveis por especialidade, cliente agenda cada OS separadamente (técnicos e durações podem diferir — duração definida pelo técnico no orçamento), sistema sugere técnico, admin confirma. Futuro: totalmente automático. Cliente nunca escolhe técnico. Admin pode reatribuir se necessário (módulo Operação). Perfil do técnico designado acessível (foto, nome, bio, especialidades, avaliações, portfólio) — disponível se quiser ver, não obrigatório.

Instant Booking Híbrido

8. Reagendamento / Cancelamento

Três atores podem reagendar/cancelar com regras diferentes: (1) Cliente — até 24h antes, sem taxa. Dois canais: site (requer Google OAuth — não disponível por token) ou wa.me pro número da empresa (atendimento humano cancela no sistema). Dentro de 24h → bloqueado no sistema, tela redireciona pra wa.me do admin (decide caso a caso). Notifica técnico + admin. (2) Técnico — pode reagendar OS atribuída a ele. Cancelar só com motivo obrigatório (auditoria). Notifica cliente + admin. (3) Admin (módulo Operação) — pode reagendar/cancelar qualquer OS, inclusive em lote ("cancelar todas de hoje"). Notifica todos envolvidos. Cancelamento libera slot automaticamente (volta pro instant booking). Reagendamento abre nova seleção de slot. Histórico de alterações + motivos registrado na solicitação.

Reagendamento Multi-Ator

9. Acompanha Status do Técnico

Técnico sinaliza "a caminho" → cliente notificado (Fase 1: técnico envia wa.me 1 tap; Fase 4: Cloud API). Link da solicitação mostra botão "Estou aqui" — cliente confirma presença com 1 tap (disponível por token, sem login). Técnico vê confirmação na visão interna + botão wa.me pra contato direto (1 tap). Se cliente não confirmou após X minutos, técnico vê alerta e pode ligar via wa.me antes de sair. Não bloqueia — técnico decide se vai.

Rastreamento + wa.me

10. Conclusão + Pagamento

Técnico tira foto do serviço finalizado, registra observações/resolução e confirma conclusão. Pagamento só para OS paga (Normal, Express, Complementar) — OS Preventiva e Garantia terminam em CONCLUÍDA sem pagamento. Evolui por fase: Fase 1 — técnico conclui OS → registra forma de pagamento (manual: dinheiro/Pix direto/transferência) → confirma recebimento na plataforma → PAGA. Sem checkout digital. Fase 3 — + checkout digital via Mercado Pago (link/QR individual por OS). Se múltiplas OS concluídas na mesma solicitação, checkout mostra opção "pagar tudo junto" com total consolidado — cliente escolhe. Nenhuma OS bloqueia pagamento de outra. Descontos de assinante aplicados por OS. Webhook atualiza status. Pagamento manual continua como alternativa. Se Pix expira ou cartão recusa: lembrete dia 1 e dia 3 (Fase 3: admin wa.me manual; Fase 4: + e-mail Resend + Cloud API), novo link gerado. Fase 5 — + upsell de assinatura com economia visível antes do pagamento — só se cliente não é assinante (aparece uma vez só) + social proof. Cliente pode adicionar assinatura e pagar tudo junto (serviço + primeira mensalidade).

Pagamento por Fase

11. Recebe Garantia Formal

Certificado de garantia de mão de obra (Fase 1-3: dados visíveis na página da OS, imprimível via browser; Fase 4: PDF gerado via React PDF + enviado por e-mail). Prazo definido por tipo de serviço (ex: Elétrica 12 meses, Pintura 6 meses). Na OS finalizada (CONCLUÍDA ou PAGA) e no certificado: botão "Acionar Garantia" visível enquanto prazo válido — requer Google OAuth (não disponível por token). Sem Google, cliente envia wa.me pro número da empresa (atendimento humano aciona no sistema). Ao clicar: mini-formulário (descrição do problema + foto obrigatória). Sistema valida prazo automaticamente contra data de pagamento da OS original paga (âncora) — prazo não reseta em regarantia. Se existe Orçamento Complementar rejeitado na OS original → sistema sinaliza pro admin (módulo Garantias) com detalhes. Admin decide se garantia se aplica (correspondência problema-complementar = julgamento humano). Se não se aplica → admin marca com motivo, cliente recebe aviso com contexto. Se válido → OS original transita pra GARANTIA_ABERTA (estado terminal) e sistema gera nova OS tipo GARANTIA sem custo.

Garantia + Validação Inteligente

12. Recebe Documentação

Evolui por fase: Fase 1 — fotos antes/depois visíveis no link da OS. Arquivos em Cloudflare R2 (10 GB free, zero egress). URLs assinadas pra acesso privado — fotos de OS não são públicas. Fase 2 — + e-mail (Resend) com link pra documentação. Portfólio aprovado = cópia pública separada (técnico marca, admin aprova). Fase 4 — + fatura PDF e certificado garantia PDF (React PDF server-side). Notificação por prioridade: WhatsApp (Cloud API) pra ação imediata, e-mail (Resend) pra documentação PDF. Documentos acessíveis no portal a qualquer momento (Fase 3+).

Documentação + R2

13. Avalia o Serviço

Recebe pedido de avaliação multicanal (WhatsApp + e-mail se Google vinculado) com link direto pra avaliar no site. Avaliação disponível por token sem verificação extra (baixa fricção — token único por solicitação). Admin pode invalidar avaliação no módulo Marketing se abuso. Nota por OS (não por Solicitação): tela única agrupa todas as OS — cliente avalia cada uma separadamente (estrelas individuais) + comentário geral opcional. Cada nota vinculada à OS e ao técnico responsável. Se não avalia, lembrete único 48h depois — sem insistir. Se todas as notas ≥ 4★, recebe link direto para avaliar no Google Business + link de indicação (referral). Reputação da empresa cresce organicamente.

Avaliações + Google Business + Indicação

14. Portal — Histórico e Faturas

Fase 1-2: cliente acompanha tudo pelo link da solicitação (token). Fase 3+: área logada (Google OAuth) com histórico completo: lista de todas as solicitações (múltiplas simultâneas permitidas) com status individual, OS, fotos antes/depois, faturas (Fase 4+), certificados de garantia (Fase 4+), garantias ativas, link de indicação.

Portal do Cliente

15. Plano de Manutenção (opcional)

Fase 5 inteira. Três canais de assinatura: (1) Checkout digital — upsell com economia visível antes do pagamento (só se não é assinante). (2) Presencial — técnico mostra detalhes no PWA, cliente aceita. Pagamento no dispositivo do cliente (QR ou link wa.me → Pix pro Pix da empresa ou cartão via MP). Técnico não toca em dados financeiros. (3) QR na hora — cliente escaneia, vai direto pra página de assinatura. Todos os canais: visitas preventivas, desconto em serviços, prioridade no agendamento. Cobrança recorrente via Mercado Pago (MP gerencia inadimplência). E-mail de boas-vindas (Resend). Upgrade/downgrade: admin ajusta no portal MP. Cancelamento: efetivo no fim do ciclo — preventivas dentro do ciclo acontecem; ao efetivar, sistema cancela futuras via webhook.

Remoto

R1. Acessa Painel do Técnico

Loga com Google OAuth — sistema reconhece como técnico pelo e-mail cadastrado. Três visões: (1) OS atribuídas — agenda do dia, OS já agendadas pra ele. (2) OS abertas sem atribuição — fila geral filtrada por especialidade do técnico (só vê categorias que tem cadastradas). Pode se atribuir a uma OS e montar orçamento — sem precisar de módulo Operação. Pode devolver OS antes de montar orçamento (estado NOVA) com motivo breve obrigatório — OS volta pra fila. Depois de orçar (ORÇADA+), só cancela com motivo completo. (3) Link direto — recebe link de solicitação específica (via notificação ou admin). Toda interação pela plataforma: orçamentos, status, notas. Nada por fora.

Painel + Self-Assign

R2a. Orçamento Remoto ✓

Info do formulário suficiente. Seleciona itens do catálogo (preço base × quantidade) + deslocamento (técnico informa km ida+volta → sistema calcula custo: km × preço_litro ÷ km_por_litro — config no módulo Operação). Técnico pode ajustar valor final. Envia orçamento ao cliente pelo sistema. Cliente aprova pelo link (assinatura digital) → agenda slot → técnico recebe notificação.

R2b. Visita Técnica ✦

Info insuficiente pra orçar remotamente. Técnico agenda visita de avaliação. No local: tira fotos melhores, descreve problema real, monta orçamento presencial. Cliente pode aprovar ali (assinatura na tela, dois checkboxes: LGPD + orçamento) ou receber link pra aprovar depois (fluxo remoto normal, 7 dias). Se aprovação presencial e técnico julga que pode executar na hora → transição APROVADA → EM_EXECUÇÃO direta (permitido quando técnico já está NO_LOCAL). Decisão do técnico, sem critério formal. Fotos da avaliação servem como foto "antes" — PWA não exige nova foto se já tirou no mesmo local.

R3. Recebe Notificação de Agendamento

Cliente aprovou e agendou → técnico notificado. Fase 1: técnico vê no painel ao acessar. Fase 2: + push notification no PWA (service worker). Vê data, horário, endereço, detalhes do serviço. Agenda do dia atualizada automaticamente. Se visita técnica com aprovação presencial e serviço simples, técnico pode executar na hora — estados de deslocamento da visita ficam no histórico (aconteceram de verdade), OS transita APROVADA → EM_EXECUÇÃO direta (permitido quando técnico já está NO_LOCAL). OS continua tipo NORMAL. Reagendamento/cancelamento: antes de A_CAMINHO → reagenda livre (novo slot). Depois de A_CAMINHO → motivo obrigatório. Cancelamento sempre com motivo — OS volta pra fila (AGENDADA sem técnico) pra reatribuição. Em execução: não cancela, cria OS Complementar ou registra motivo como metadado "aguardando complementar".

Notificação + Reagendamento

R4. Sinaliza "A Caminho"

Toca botão "A caminho" no PWA. Cliente notificado (Fase 1: técnico envia wa.me 1 tap; Fase 4: Cloud API proativa). Cliente confirma presença no link da solicitação. Técnico vê confirmação + botão wa.me pra contato direto (1 tap). Se cliente não está, evita viagem perdida.

Rastreamento Manual

R5. Sinaliza "Cheguei"

Chegou no local → toca botão. Cliente notificado (mesma escada de R4). Registro de horário de chegada automático (timestamp).

Rastreamento Manual

Mínimo 1 foto obrigatória do estado atual via câmera do celular. PWA bloqueia avanço sem foto. Foto salva com timestamp e geolocalização. Pode tirar mais se quiser. Funciona sem sinal. → Converge para Execução em Campo.

Express

E1. Cria Solicitação + OS Express

Cliente chamou técnico direto (sem formulário prévio). Técnico cria solicitação express no PWA: primeiro consentimento LGPD (checkbox na tela, cliente aceita antes de qualquer dado), depois WhatsApp do cliente + categoria(s) + endereço (geolocalização 1 tap — técnico já está no local, geocoding reverso preenche endereço). Solicitação + OS geradas juntas (1 por categoria). OS nasce diretamente em ORÇADA (pula NOVA) com técnico criador já atribuído — nunca aparece na fila pública de OS abertas. Não passa por fila — técnico já está no local.

Criação Express + LGPD

E2. Foto do "Antes" (obrigatória)

Mínimo 1 foto obrigatória antes de qualquer coisa. Documenta problema e registra estado pré-trabalho (dois propósitos, uma foto). PWA bloqueia avanço sem foto. Foto salva com timestamp e geolocalização. Funciona sem sinal.

PWA Offline + Camera API

E3. Monta Orçamento Presencial

Seleciona itens do catálogo (preço base × quantidade) + deslocamento (técnico informa km → sistema calcula custo pela fórmula de combustível, pode ajustar). Fotos do "antes" já vinculadas ao orçamento. Mostra na tela do PWA pro cliente.

Orçamento no Local

E4a. Aprovação Presencial ✓

Cliente assina na tela do técnico. Checkbox de aprovação do orçamento + assinatura capturada (LGPD já coletado no E1). Registro auditável. Estados de deslocamento = "N/A — express". → Converge para Execução em Campo.

E4b. Rejeição / Indecisão ✗

Cliente recusa orçamento. Técnico pode ajustar valor e reapresentar no ato (renegociação natural, sem limite, sem estado especial — OS continua ORÇADA). Se recusa definitiva → OS vai pra REJEITADA com motivo opcional. Remarketing 48h (mesma escada: Fase 1 admin wa.me; Fase 2 e-mail; Fase 4 Cloud API). Se cliente quer pensar → OS fica ORÇADA, tipo continua EXPRESS. Cliente recebe link pra aprovar remotamente. Se aprovar depois e técnico não está mais no local → segue agendamento normal (APROVADA → AGENDADA → etc).

Preventiva

Fase 5: sistema gera automaticamente pelo calendário do plano (Básico: 1/semestre, Conforto: 2/semestre, Premium: 4/ano). Em ambos: técnico recebe na agenda com status AGENDADA. Sem orçamento — coberta pelo plano. Admin/cliente pode reagendar.

Checklist por Categoria

P4. Relatório + OS Complementar

Checklist preenchido + fotos + observações → relatório (Fase 1: dados visíveis no link da OS, técnico envia wa.me; Fase 2: + e-mail Resend com link; Fase 4: PDF gerado + enviado multicanal). Garantia

G1. Recebe OS Garantia

Cliente acionou garantia → sistema validou (prazo OK contra data de pagamento da OS original paga — prazo não reseta em regarantia, sem complementar rejeitado) → gera OS tipo GARANTIA vinculada à OS original paga (âncora de prazo). Regarantia permitida enquanto dentro do prazo original. Admin pode override caso a caso. Atribuição: técnico original primeiro (conhece o contexto). Se indisponível (saiu, férias, lotado) → cai na fila filtrada por especialidade. Admin pode override. Sem orçamento — coberta pela garantia.

Atribuição Inteligente

G2. Desloca + Foto Antes

Mesmos passos de deslocamento do Remoto (A Caminho → Cheguei). Foto antes obrigatória — registra estado do problema reportado pelo cliente. Técnico tem acesso ao histórico da OS original (fotos, notas, o que foi feito).

Rastreamento + Contexto

G3. Executa Correção

Executa reparo do problema coberto pela garantia. Registra notas e observações no PWA. Sem pagamento — OS Garantia é sem custo (CONCLUÍDA, sem PAGA). Se descobrir problema fora do escopo da garantia → pode criar OS Complementar (paga). → Converge para Execução em Campo (C3 em diante, pula C5 — garantia não tem pagamento).

Correção sem Custo
Execução em Campo

C1. Executa Serviço

Realiza o trabalho. Registra notas, materiais consumidos e observações no PWA. Tudo salvo localmente (offline). Sincroniza automaticamente quando voltar online.

PWA Offline

C2. Orçamento Complementar (se necessário)

Descobriu serviço adicional não previsto (ex: fiação precisa trocar)? Técnico monta orçamento complementar direto na mesma OS pela plataforma. Gera OS tipo COMPLEMENTAR vinculada à OS pai. OS nasce diretamente em ORÇADA com técnico criador já atribuído (técnico já está no local — nunca entra na fila pública). Aprovação depende da presença: cliente no local → assina na tela do técnico (aprovação presencial), OS Complementar pula pra EM_EXECUÇÃO. Cliente ausente → notificação multicanal. Técnico continua escopo original ou registra motivo "aguardando complementar" como metadado na OS (se não pode continuar sem aprovação). Não existe estado PAUSADA. Se cliente aprova remotamente → OS Complementar vai pra APROVADA → agendamento normal (prioriza técnico original, não garante). Deslocamento na OS Complementar com aprovação remota = decisão do admin caso a caso. Valor adicional somado ao checkout final.

Técnico pode marcar foto como "boa pra portfólio" no PWA → admin (módulo Marketing) aprova antes de publicar. Nenhuma foto vai pro público sem aprovação. Fotos internas da OS ≠ fotos públicas.

PWA Offline + Camera API

Conclusão

C5. Pagamento (só OS paga)

Só pra OS paga (Normal, Express, Complementar). Pagamento nunca obrigatório pra concluir OS. Dados sincronizam quando voltar online. Evolui por fase: Fase 1 — técnico registra forma de pagamento (dinheiro/Pix direto/transferência) → confirma recebimento na plataforma → PAGA. Sem checkout digital. Fase 5 — + upsell de assinatura com economia visível antes do pagamento (só se não é assinante, aparece uma vez). Técnico mostra tela, cliente aceita. Paga tudo junto (serviço + primeira mensalidade).

C6. Pedido de Avaliação

Pedido de avaliação ao cliente após conclusão (Fase 1: técnico envia link wa.me; Fase 2: + e-mail Resend; Fase 4: + Cloud API). Nota por OS, tela única (mesma mecânica do passo 13 do cliente). Técnico acumula nota e portfólio (fotos antes/depois) no perfil.

Máquina de Estados — Ordem de Serviço

Tipos de OS

NORMAL (formulário remoto, pago, fluxo completo) · EXPRESS (técnico cria no local, pago, pula agendamento) · COMPLEMENTAR (extra descoberto, pago, vinculada a OS pai) · PREVENTIVA (sistema automático por plano, sem custo, recorrente) · GARANTIA (cliente aciona, sem custo, vinculada a OS original). Todos usam mesma máquina de estados.

Fluxo Principal

NOVA → ORÇADA → APROVADA → AGENDADA → A_CAMINHO → NO_LOCAL → EM_EXECUÇÃO → CONCLUÍDA → PAGA

Caminhos Alternativos

ORÇADA → REJEITADA (cliente rejeita) · ORÇADA → EXPIRADA (7 dias sem resposta) · EXPIRADA → ORÇADA (admin reativa com novo prazo — técnico revisa preço se necessário) · REJEITADA → ORÇADA (idem — admin reativa) · Qualquer estado → CANCELADA (cliente até 24h antes, técnico com motivo, admin qualquer momento)

Garantia

PAGA → GARANTIA_ABERTA ou CONCLUÍDA → GARANTIA_ABERTA (estado terminal da OS original). OS paga (Normal, Express, Complementar) transita de PAGA. OS Garantia (regarantia de correção) transita de CONCLUÍDA. OS Preventiva não gera garantia — é inspeção, não mão de obra. Sistema gera nova OS tipo GARANTIA (sem custo): AGENDADA → A_CAMINHO → NO_LOCAL → EM_EXECUÇÃO → CONCLUÍDA. Validação de prazo = automática. Correspondência com complementar rejeitado = decisão humana (admin sinalizado).

Caminhos por Tipo

NORMAL: NOVA → ORÇADA → APROVADA → AGENDADA → A_CAMINHO → NO_LOCAL → EM_EXECUÇÃO → CONCLUÍDA → PAGA. EXPRESS: ORÇADA → APROVADA → EM_EXECUÇÃO → CONCLUÍDA → PAGA (nasce em ORÇADA — técnico criador já atribuído, nunca entra na fila pública). COMPLEMENTAR (presencial): ORÇADA → APROVADA → EM_EXECUÇÃO → CONCLUÍDA → PAGA (nasce em ORÇADA — técnico criador já atribuído). COMPLEMENTAR (ausente): ORÇADA → APROVADA → AGENDADA → A_CAMINHO → NO_LOCAL → EM_EXECUÇÃO → CONCLUÍDA → PAGA. PREVENTIVA: AGENDADA → ... → CONCLUÍDA (sem PAGA). GARANTIA: idem Preventiva. Transição APROVADA → EM_EXECUÇÃO direta permitida quando técnico já está NO_LOCAL.

Transições (não são estados)

Reagendamento = AGENDADA → AGENDADA (novo slot). Cancelamento libera slot automaticamente. Orçamento complementar: técnico continua escopo original ou registra metadado "aguardando complementar" em EM_EXECUÇÃO (não existe estado PAUSADA). Express sem aprovação presencial: OS fica ORÇADA, tipo continua EXPRESS, aprovação remota → agendamento normal se técnico não está mais no local.

Quem muda estado

Sistema: NOVA, EXPIRADA, AGENDADA (auto). Cliente: APROVADA, REJEITADA, GARANTIA_ABERTA (terminal — de CONCLUÍDA ou PAGA, gera OS GARANTIA nova), CANCELADA. Técnico: ORÇADA, A_CAMINHO, NO_LOCAL, EM_EXECUÇÃO, CONCLUÍDA, CANCELADA (com motivo). Admin: qualquer transição (override). Sistema/Técnico: PAGA (webhook MP ou confirmação manual).

Integrações entre os Fluxos

Solicitação → OS → Orçamento

Cliente preenche form (múltiplas categorias permitidas) → wa.me envia pro WhatsApp da empresa com link → 1 Solicitação gera N ordens de serviço automaticamente (1 por categoria). 1 OS = 1 categoria = 1 técnico = 1 garantia (sem merge). Mesmo que um técnico faça tudo, são OS separadas. Cliente vê solicitação com OS filhas agrupadas no portal. Checkout consolida (paga tudo junto ou separado por OS).

Aprovação → Agendamento → Técnico

Cliente aprova orçamento → agenda data/horário → técnico recebe notificação push no PWA + painel interno atualizado

Link Único — Role Detection

Mesmo link da solicitação pra todos. Google login = visão cliente (leitura). Conta interna = visão técnico (edição). Primeiro Google vira dono.

Conclusão → Upsell → Pagamento

Técnico conclui + foto → checkout com upsell de assinatura → Mercado Pago (Pix/cartão) ou pagamento manual confirmado pelo técnico → webhook atualiza status

Notificação por Prioridade

WhatsApp (Cloud API) pra ação imediata: orçamento pronto, técnico a caminho/chegou, lembrete pagamento, remarketing, avaliação. E-mail (Resend) pra documentação: fatura PDF, fotos antes/depois, certificado garantia, resumo mensal assinante, boas-vindas assinatura. Otimiza custo Cloud API sem sacrificar experiência. Status visível no portal se logado.

Orçamento Complementar

Técnico descobre serviço adicional no local → monta orçamento complementar (OS tipo COMPLEMENTAR, vinculada a OS pai). Cliente presente → aprova na tela, pula pra EM_EXECUÇÃO. Cliente ausente → notificação, se aprova → APROVADA → agendamento normal (prioriza técnico original, não garante; deslocamento = decisão admin caso a caso). Se rejeita → REJEITADA (registro na OS pai = proteção garantia). Valor somado ao checkout.

Conclusão → Garantia + Documentação

OS concluída → gera certificado de garantia PDF + fatura + fotos antes/depois → enviado multicanal (WhatsApp + e-mail). Botão "Acionar Garantia" visível enquanto prazo válido.

Avaliação → Google Business

Cliente avalia ≥ 4★ internamente → recebe link direto pro Google Review. ≤ 3★ → admin trata antes. Lembrete único 48h se não avaliou.

Remarketing + Expiração

Orçamento expira em 7 dias (lembretes dia 3 e 6). Rejeição → remarketing 48h. Inativos 6+ meses → reativação. Tudo multicanal.

Garantia → Chamado → OS

Cliente clica "Acionar Garantia" na OS → descrição + foto → sistema valida prazo → se válido, abre OS de correção sem custo automaticamente

Rastreio Total → Dados

Toda interação registrada no sistema: orçamentos, decisões, pagamentos, avaliações → ativo de dados pra insights de marketing, campanhas, padrões de demanda e melhorias

Assinatura → Prioridade + Desconto

Cliente assinante recebe desconto automático no checkout e prioridade no agendamento. Upsell oferecido antes do pagamento com economia visível.
